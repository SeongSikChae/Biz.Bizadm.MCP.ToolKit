# R01 마일스톤 관리

## 목적

사용자는 GitHub 저장소의 마일스톤을 MCP 안에서 만들고, 고치고(닫기·다시 열기 포함), 지우고, 닫힌 것까지 마감일·진행률과 함께 보려 한다. GitHub MCP Server는 이슈에 마일스톤 번호를 붙이는 것(`issue_write`의 `milestone`)과 UI용 목록(`ui_get`)만 제공하므로(2026-11-24 `github_list_tools`로 `SeongSikChaeGitHub` 인스턴스의 Tool 목록을 조회해 확인), 나머지를 GitHub REST API로 채운다.

## 지금 동작

- GitHub REST Tool(`GitHubRefTools`, `GitHubReleaseTools`, `GitHubRateLimitTools`)은 `GitHubRestClient.SendAsync`로 요청한다. 이 메서드가 `Authorization: Bearer`·`Accept: application/vnd.github+json`·`X-GitHub-Api-Version: 2022-11-28`·`User-Agent` 헤더를 싣고, 실패를 `McpException`(Token 없음)으로 바꾸며, 재시도하지 않는다.
- `instance`가 비었거나 등록되지 않았으면 `GitHubRestClient.Resolve`가 요청 없이 `instance is required. Registered instances: ...` 또는 `Unknown GitHub instance '...'. Registered instances: ...` 오류를 낸다.
- `owner`·`repo`는 `GitHubRestClient.RepoPath`가 세그먼트마다 URL 인코딩하고, 빈 값·`.`·`..`는 거부한다.
- `GitHubMilestoneTools`(마일스톤 Tool 다섯)는 목록 요청에 `SendAsync`의 `Uri` 오버로드를 쓰며 요청 주소에만 쿼리를 붙이고 오류 메시지의 경로에는 쿼리를 넣지 않는다. `dueOn`(`YYYY-MM-DD`)은 `T12:00:00Z`(UTC 정오)를 붙여 `due_on`으로 보내고, `clearDescription`·`clearDueOn`은 해당 필드를 JSON `null`로 보낸다. 값 목록 입력은 공백을 뗀 뒤 소문자와 정확히 같아야 한다.
