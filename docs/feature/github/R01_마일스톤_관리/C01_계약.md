속한 스펙: `R01`

## 호환 규칙

- 바꿔도 되는 것: Tool 설명 문구, 선택 입력 추가, 오류 메시지의 요약 부분(`: ` 뒤).
- 결정 문서가 있어야 하는 것: Tool 이름, 입력 이름·형 변경과 삭제, 필수 입력 추가, 반환 모양(`github_delete_milestone`의 `{"deleted":{"milestoneNumber":n}}`, 나머지는 GitHub 응답 그대로), 힌트 변경.

## 공통

입력 (다섯 Tool 모두)

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `instance` | string | 예 | GitHub 인스턴스 이름. `github_list_instances`로 확인 |
| `owner` | string | 예 | 저장소 소유자(사용자 또는 조직) |
| `repo` | string | 예 | 저장소 이름 |

- 문자열 입력은 앞뒤 공백을 뗀다. 공백만 있으면 주지 않은 것으로 본다.
- 값 목록 입력(`state`·`sort`·`direction`)은 공백을 뗀 뒤 적힌 소문자 값과 정확히 같아야 한다. 대문자가 섞이면 목록 밖 값으로 본다(`D01_02`).
- `milestoneNumber`는 마일스톤의 `number`(저장소 안 번호)이며 응답의 `id`가 아니다.

공통 오류 (요청 없이 난다)

| 메시지 | 나는 조건 |
| --- | --- |
| `instance is required. Registered instances: ...` | `instance`가 없다 |
| `Unknown GitHub instance '<이름>'. Registered instances: ...` | 등록되지 않은 이름 |
| `owner is required.` / `repo is required.` | `owner`·`repo`가 없다 |
| `owner must not contain empty, '.' or '..' path segments.` (repo도 같음) | `owner`·`repo`가 `.` 또는 `..` |
| `milestoneNumber must be a positive integer.` | `milestoneNumber`가 필요한 Tool에서 없거나 0 이하 |

GitHub 오류

| 메시지 | 나는 조건 |
| --- | --- |
| `GitHub '<인스턴스>' <메서드> <경로> failed (HTTP <코드>): <message (errors)>` | GitHub가 2xx가 아닌 응답(404 없음, 403 권한 없음, 422 검증 실패 등) |
| `GitHub '<인스턴스>' <메서드> <경로> failed: <예외 메시지>` | 연결 실패 |
| `GitHub '<인스턴스>' <메서드> <경로> returned no content.` | 본문이 있어야 하는 호출(목록·조회·생성·수정)이 빈 본문 |

- `<경로>`에는 쿼리를 넣지 않는다. 오류 메시지에 Token을 넣지 않는다. 재시도하지 않는다.

권한 (다섯 Tool 모두)

- GitHub 문서 "Permissions required for fine-grained personal access tokens"(https://docs.github.com/en/rest/authentication/permissions-required-for-fine-grained-personal-access-tokens, 2026-11-24 조회)는 마일스톤 목록·조회(`GET`)를 저장소 권한 "Issues"와 "Pull requests"의 read에, 생성·수정·삭제(`POST`·`PATCH`·`DELETE`)를 두 권한의 write에 함께 올리고, 모두 "추가 권한"(둘 이상이 필요하거나 묶음 가운데 하나가 필요함) 표시를 단다.
- 두 권한이 모두 필요한지 둘 중 하나면 되는지는 마일스톤 API 문서(https://docs.github.com/en/rest/issues/milestones)에서도 확인하지 못했다(미확인). 권한이 모자라면 GitHub가 403 또는 404를 돌려준다(미확인).

## C01-I1 github_list_milestones

힌트: 읽기 전용 · 멱등 · 비파괴 · 외부 접근

입력 (공통 외)

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `state` | string | 아니오 | `open` / `closed` / `all`. 생략하면 GitHub 기본(`open`) |
| `sort` | string | 아니오 | `due_on` / `completeness`. 생략하면 GitHub 기본(`due_on`) |
| `direction` | string | 아니오 | `asc` / `desc`. 생략하면 GitHub 기본(`asc`) |
| `perPage` | integer | 아니오 | 1~100. 생략하면 GitHub 기본(30) |
| `page` | integer | 아니오 | 1 이상. 생략하면 1 |

요청

- `GET repos/{owner}/{repo}/milestones`. 준 값만 `state`·`sort`·`direction`·`per_page`·`page` 순서의 쿼리로 붙인다. 본문 없음.

출력

- GitHub 응답(마일스톤 배열) 그대로. 항목에 `number`·`title`·`state`·`description`·`due_on`·`open_issues`·`closed_issues`·`closed_at`·`html_url`이 있다(미확인).

오류 (요청 없이 난다, 공통 외)

| 메시지 | 나는 조건 |
| --- | --- |
| `state must be one of: open, closed, all.` | 목록 밖 값 |
| `sort must be one of: due_on, completeness.` | 목록 밖 값 |
| `direction must be one of: asc, desc.` | 목록 밖 값 |
| `perPage must be between 1 and 100.` | 범위 밖 |
| `page must be a positive integer.` | 0 이하 |

코드

## C01-I3 github_create_milestone

힌트: 쓰기 · 비멱등 · 비파괴 · 외부 접근

입력 (공통 외)

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `title` | string | 예 | 마일스톤 제목 |
| `state` | string | 아니오 | `open` / `closed`. 생략하면 GitHub 기본(`open`) |
| `description` | string | 아니오 | 설명 |
| `dueOn` | string | 아니오 | 마감일 `YYYY-MM-DD` |

요청

- `POST repos/{owner}/{repo}/milestones`. 본문은 `title`과 준 값만: `{"title", "state", "description", "due_on"}` 순서.
- `dueOn`은 `due_on`에 `YYYY-MM-DDT12:00:00Z`로 보낸다. GitHub는 마감일의 날짜만 쓰며, 자정(UTC)으로 보내면 시간대에 따라 하루 앞 날짜로 보일 수 있어 UTC 정오로 보낸다(미확인, `R01-A4`로 확인).

출력

- GitHub 응답(마일스톤) 그대로.

오류 (요청 없이 난다, 공통 외)

| 메시지 | 나는 조건 |
| --- | --- |
| `title is required.` | `title`이 없다 |
| `state must be one of: open, closed.` | 목록 밖 값 |
| `dueOn must be a date in YYYY-MM-DD format.` | 형식이 다르거나 없는 날짜(예: `2026-02-30`) |

코드

## C01-I4 github_update_milestone

힌트: 쓰기 · 멱등 · 파괴 · 외부 접근

입력 (공통 외)

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `milestoneNumber` | integer | 예 | 마일스톤 번호. 양수 |
| `title` | string | 아니오 | 새 제목 |
| `state` | string | 아니오 | `open`(다시 열기) / `closed`(닫기) |
| `description` | string | 아니오 | 새 설명 |
| `dueOn` | string | 아니오 | 새 마감일 `YYYY-MM-DD` |
| `clearDescription` | boolean | 아니오 | true면 설명을 지운다. 기본 false |
| `clearDueOn` | boolean | 아니오 | true면 마감일을 지운다. 기본 false |

요청

- `PATCH repos/{owner}/{repo}/milestones/{milestoneNumber}`. 본문은 준 값만 `{"title", "state", "description", "due_on"}` 순서로 담는다. `clearDescription`이면 `"description":null`, `clearDueOn`이면 `"due_on":null`. `dueOn` 변환은 `C01-I3`과 같다.

출력

- GitHub 응답(마일스톤) 그대로.

오류 (요청 없이 난다, 공통 외)

| 메시지 | 나는 조건 |
| --- | --- |
| `at least one field to update is required.` | 바꿀 값이 하나도 없다 |
| `state must be one of: open, closed.` | 목록 밖 값 |
| `dueOn must be a date in YYYY-MM-DD format.` | 형식이 다르거나 없는 날짜 |
| `description and clearDescription cannot be used together.` | 둘 다 줌 |
| `dueOn and clearDueOn cannot be used together.` | 둘 다 줌 |

코드

- `src/Biz.Bizadm.MCP.ToolKit/Tools/GitHub/GitHubMilestoneTools.cs`: `GitHubMilestoneTools.UpdateMilestone`

## C01-I5 github_delete_milestone

힌트: 쓰기 · 멱등 · 파괴 · 외부 접근

입력 (공통 외)

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `milestoneNumber` | integer | 예 | 마일스톤 번호. 양수 |

요청

- `DELETE repos/{owner}/{repo}/milestones/{milestoneNumber}`. 본문 없음. GitHub는 204를 돌려준다(미확인). 지운 마일스톤에 붙어 있던 이슈·PR의 마일스톤은 비워진다(미확인).

출력

- `{"deleted":{"milestoneNumber":<번호>}}`

오류

- 공통 오류만. 없는 번호면 GitHub가 404를 돌려준다(미확인).

코드

- `src/Biz.Bizadm.MCP.ToolKit/Tools/GitHub/GitHubMilestoneTools.cs`: `GitHubMilestoneTools.DeleteMilestone`
